# Design

## Context

See proposal.md for the publication need. The original publication base contained the earlier plaintext provider and registry stores, one executor supervisor and a fixed engine provider. The active local source already implements the required APIs under approved credential, Claude and runtime-provider plans. This change extracts their coherent dependency closure into a clean checkout instead of publishing that checkout's unrelated work.

## Goals / Non-Goals

**Goals:** Keep one credential implementation, one governor, bounded native child supervision and idle provider configuration. Preserve public constructors and the existing wire protocol. Make every required source, fixture and documentation change reviewable below central PR limits.

**Non-Goals:** Native platform support certification, site redesign, model catalogs, SDK portability, package installation changes, public visibility, release packaging or deployment.

- Reuse the existing AWS-LC AEAD dependency for a bounded authenticated envelope and the maintained keyring-core native stores for its key. The encrypted payload is capped before decoding. The protected-file adapter uses safe Rustix on Unix and RightKit on Windows/macOS. Keep only thin path, transaction, migration and namespace policy in project code. See docs/credential-vault.md for package fit, budgets and recovery.
- Retain the provider store's stable legacy lock and publish an unsupported-version barrier only after verified encrypted commit. Keep registry imports explicit because old registry writers do not share that lock. Destination markers survive deletion and prevent stale reimport. Open Unix legacy registry sources with the existing maintained Rustix nonblocking and no-follow flags before validating the descriptor as a private regular file. A FIFO must fail without waiting for a writer, deleting its source or changing the encrypted destination. Protect this with a bounded Linux FIFO regression whose joined watchdog releases a regressed blocking open and records that rescue as a failure.
- Bound asynchronous vault acquisition, including native key access, by the caller's cancellation token and one 30-second deadline. Keep the prepared transaction inside the blocking worker through each synchronous native call. Check cancellation and the deadline before later key or durable effects and before returning a transaction. An already-started key write may finish after cancellation; keep its durable bootstrap marker so retry recovers the same key instead of replacing it.
- Reuse the official unmodified Claude Code client. Auth stays independent of execution and terminal code. The provider uses the shared executor with bounded private stdin, clears ambient auth/routing overrides and rechecks subscription status before every inference. Native tools and ordinary customizations are disabled while managed provider policy remains effective.
- Keep child ownership in a small executor adapter. Unix process groups and maintained Windows Job ownership retain pending cleanup. In the auth adapter, retire a Unix numeric group identity synchronously only after group termination and child reaping succeed, before later output-drain waits. Keep that identity armed through every cleanup await and error so abandoned cleanup still owns its child group. Preserve Windows Job ownership and the existing executor lease contract. Do not include unrelated package-host or SDK process changes.
- Persist provider binding and continuation removal in one SQLite transaction under admission ownership. Extract only that journal hunk, preserving the base journal implementation and excluding native SQLite file-hardening work.
- Keep the ordinary registry suite independent of the current user's OS key service. Its existing injected-key test already covers encrypted round-trip, origin separation, redaction, deletion and stale-import prevention; remove only the obsolete integration case that duplicates those assertions through the native store. Keep real native-store acceptance explicitly opt-in and retain every asynchronous 30-second deadline and lock-ownership regression.
- Update the base static public documentation directly. Do not copy the concurrent React/Vite site migration. Document source availability and unverified native acceptance explicitly.

## Risks / Trade-offs

- OS key service access can block or fail. Tokio cannot stop an already-started blocking call: asynchronous callers return on cancellation or their deadline, but the worker retains the stable lock until the OS call returns. Later acquisition remains bounded and cannot initialize a competing key. The explicitly synchronous `lock_blocking` boundary cannot interrupt native calls and must run off event threads. Errors preserve encrypted state and explicit memory-only selection never happens silently.
- Encryption and native key dependencies add build and runtime cost. The existing local measurements are prior-checkout evidence, not proof for this extraction. Repeat the documented credential workload before acceptance.
- Claude launches a process per check and inference and returns a final text delta. Offline fixtures do not prove live subscription behavior or native Windows cleanup.
- The current protected caller prerequisite is merged at `99ba4575ad9070a7a0f3296a35e746858af904b0`. It supplies Linux D-Bus build setup and strict review completion through retained shared revision `c4f2873ef0eef5bc3c7d75cf71fa3489a911d134`. Earlier API, corrected-runtime and locked CLI/IDE results remain bound to their named snapshots. The resumed-clock source at `90aa7350e30eaad908d14e8b3260610d5f15f2fe` passed its normal local hook. Hosted run `39299507686` then exposed the OS-store-dependent test and blocking legacy FIFO issues above. Fresh local and exact-head hosted acceptance remain required for their corrections. The final PR base and immutable dependency pin must identify the admitted source revision, and each submitted diff must remain below 200 files, 12,000 changed lines and 1 MB.
- Trimmed dependency scope requires a newly resolved Cargo lock and clean-source harness and CLI checks. Do not present earlier broad-checkout results as this snapshot's gate.

## Migration Plan

1. Extract the required source, meaningful fixtures, canonical/public docs and exact direct dependency pins.
2. Regenerate the lock through the parent-owned Cargo gate. Run focused auth, executor, package and provider fixtures, then the required harness gate and consumer checks.
3. Review the exact snapshot, publish a private draft PR only after the parent confirms it, and retain normal human admission. Keep repository visibility and Actions secrets unchanged.
4. After reviewed dependency merge, update the CLI's immutable harness revision and verify its source extraction in hosted CI. Native evidence and dedicated OAuth setup remain separate tracked prerequisites.
5. A rollback must preserve ciphertext and migration barriers. Never export credentials to plaintext or retry an old rotating token.
