# Design

## Context

Decisions come from the approved `first-public-releases` plan. This change covers
its tasks 2.1, 2.2, 3.2a, 3.4, 4.6 and the SDK packaging part of 5.6 for this
repository.

## Decisions

- **Version `0.1.1`.** A `v0.1.0` tag already exists on this repository and the
  draft flow refuses an existing tag. Versions are not lowered. `VERSION`,
  the workspace manifest and its internal pins, `registry/Cargo.toml` and its pin,
  both lock files that carry owned crates, both SDK manifests and `sdk/python/uv.lock`
  move together. The dated changelog section replaces `[Unreleased]`.
- **Trust split.** The shared standard allows only `pr.yml`, `release.yml` and an
  opt-in `build.yml`. `build.yml` holds top-level `contents: read` and nothing else,
  uses no token, secret or environment, and pins every action by full SHA. It runs
  on `workflow_dispatch` and push to main, builds with `--locked` and
  `npm ci --ignore-scripts`, and uploads per-job artifacts. A final `collect` job
  writes one `build-sha256.txt` and uploads the single `release-files` artifact.
  Adopting it also replaces `release.yml` with the canonical native caller (verify,
  Draft release, attach) generated by the standards repository, so the shared
  attach workflow, which runs no project code, attaches files to the draft.
- **Archives.** `ejm-harness-worker-<version>-<target>.tar.gz` holds the binary,
  `LICENSE` and `THIRD_PARTY_NOTICES.md`. Names use only `[A-Za-z0-9._-]`. Targets use the `releases.json` names `linux-x86_64` and
  `darwin-aarch64`.
- **Linux baseline.** The Linux job runs on the oldest hosted image the project
  accepts (`ubuntu-22.04`, glibc 2.35) and installs `libdbus-1-dev` for the
  credential store crate at build time. A local release build lists only libc,
  libm and libgcc_s as dynamic libraries (`ldd`), so the archive has no `libdbus-1`
  runtime dependency. The notes state a glibc floor only after a hosted build
  confirms it.
- **macOS held.** The macOS job builds and smokes the worker so evidence exists,
  but its artifact is named for evidence only. Notes and the future site list no
  macOS file until a notarization run is recorded. Worker command-line archives
  fetched with `curl` carry no quarantine flag, but the owner chose to wait.
- **SDK packaging.** `build.yml` packs the npm tarball and the Python sdist and
  wheel after the SDK tests, and the `collect` job includes them in the release
  files, so they can be installed from the release before registry publication.
  Registry publication (npm trusted publishing, PyPI Trusted Publishers, with a
  build job and a separate publish job that runs no project code) is not a
  permitted workflow file in this repository today. A draft publish workflow is
  parked outside the repository until the owner confirms the names and the shared
  standard offers a place for it.
- **Smoke.** `scripts/smoke-worker.py` starts the worker, sends `hello`, and checks the
  protocol and version. The workflow and local runs share it. A second
  script step runs each SDK against the binary through `EJM_HARNESS_WORKER_PATH`.
- **Issue routes.** The bug form's `evidence` field already accepts a version and
  platform by query parameter, so no form field is added. Add the private advisory
  link to `feature.yml`-adjacent config only if missing.

## Shared pin

`pr.yml` and `release.yml` pin the shared standards squash-merge commit
`451ef7d1ef46373b6018a1fbcacc331e15e1d093` on the main branch of the shared repository. Its tree equals
the reviewed `81073b4673ebefb99d6adaa649166b642091427a` (the `ejm/rel-gh` head), and `release.yml` is the canonical
native caller generated by `consumer_workflows(revision, native=True)` at the
pinned commit. `build.yml` passes that commit's `native_build` lint.

`.github/review-context` is left as is. The pinned standard has no exporter for it,
and neither reads nor requires it (its decision log records the static review data
as removed). Whether to delete the stale snapshots is a separate owner decision.

## Risks

- Hosted runners may differ from local builds. Local builds record evidence;
  hosted results are unverified until a run.
- Open native evidence stays open and is named as known limits, pending owner
  approval.
