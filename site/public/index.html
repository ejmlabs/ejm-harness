harness by ejmlabs

An open engine that runs a hundred coding agents on one governor.

A Rust library for building coding agents. Sessions that wait on a model own no shell and no thread. Every command, tool, and child agent is admitted, bounded, and journaled.

Build from source v0.1.0 source release, not yet packaged

The engine keeps the hard parts

  • Waiting costs nothing

    A session awaiting a model holds no process. Sessions are light state that share one provider, tool registry, store, and governor.

  • One governor for all work

    Commands reserve CPU, memory, processes, and output before they start. Model requests and local jobs have separate limits. A model cannot raise them.

  • Fair queues

    Requests rotate between sessions, first in first out within each. A dropped waiter leaves at once, and a lease frees every reservation when it ends.

  • Journal first, never replay

    A bounded SQLite journal records every event. After a crash, harness recovers the run and never repeats an effect whose outcome is uncertain.

  • Native file tools

    Read, list, search, write, and patch without spawning a shell. Shell access is optional and keeps normal Bash semantics when granted.

  • Guarantees stated plainly

    Each restriction is reported as enforced, monitored, or unsupported. Native execution runs as you and is not a sandbox.

TypeScript and Python share one worker

Both SDKs drive one persistent Rust worker over a JSONL protocol, shared across every session. Neither SDK has runtime package dependencies.

Custom tools stay ordinary functions in your language, with schema validation, progress, and cooperative cancellation. Credentials travel over stdin, never through arguments. 

async with AsyncHarness(
    config={"provider": {"kind": "echo"}}
) as harness:
    session = await harness.create_session(
        title="First agent"
    )
    run = await session.start("Hello")
    async for event in run:
        if event["type"] == "text_delta":
            print(event["text"], end="")

Light by design

Agent capacity, model capacity, and local job capacity are separate. A hundred waiting agents share a small pool of local work instead of a shell each.

  • 0hosted model calls in tests and benchmarks

Measured on 18 October 2026 on a Mac16,8 with 12 logical CPUs and 24 GiB RAM, using deterministic provider responses. A hundred sessions each ran three Bash checks; sampled engine resident memory was 25.72 MiB and sampled peak local jobs was 4. A modern Mac does not prove the four core, 8 GB target, and this run excludes remote model latency and coding quality.

Swap behavior at the edges

  • Provider

    Chat Completions compatible APIs, Anthropic Messages, and OpenAI Responses with an API key or ChatGPT sign-in.

  • Tool

    Native, command, or host language tools. A repository cannot grant itself a tool.

  • ContextPolicy

    What the model sees, and when history is compacted.

  • RunStrategy

    How a run picks its next step. The engine still owns grants, budgets, and journaling.

  • Hook

    Ordered interception of runs, context, tools, results, and completion.

  • Credentials

    Sign-in, storage, and serialized renewal live in their own crate. Providers only see a credential source.

Get harness

harness is a source release and has not been published or packaged yet. It needs only the pinned Rust toolchain. Rust hosts need no Node or Python runtime. 

cargo build --release --workspace --locked
cargo test --workspace --locked
